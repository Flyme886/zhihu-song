# 运行与模型配置

主开发目录是 `web/`。以下命令均在仓库根目录执行，默认只监听本机 `127.0.0.1`。

## 启动

运行需要 Python 3。前端使用原生 JavaScript 和已放入 `web/vendor/three/` 的 Three.js，直接预览不需要 npm 安装或构建。

```bash
python3 web/server.py --port 8081
```

打开[本机首页](http://127.0.0.1:8081/#/home)。也可以在安装 Node.js / npm 后执行 `npm --prefix web run dev`。

| 入口 | 路径 |
| --- | --- |
| 双世界首页 | `/#/home` |
| 知识星球，蜗牛话题 | `/#/world/snail` |
| 我的星球 | `/#/planet` |
| 记忆地图 | `/#/planet/map` |
| 讨论记录 | `/#/planet/records` |
| 本地故事演示 | `/#/planet/story/living-room` |

端口占用时可以改成 `--port 8082`，并用新端口打开页面。浏览器存储按来源隔离，更换端口后不会自动出现旧端口下的记录。

## 不配置密钥能体验哪些内容

可浏览内置话题和原回答、输入观点、漫游个人星球、运行本地故事，并使用本地保存与导出。原回答中的远程配图仍依赖图片来源可用。

对谈需要主动选择离线模式。进入「知识星球」，点击「让两种看法聊聊」，展开「对谈设置与来源选择」，将「对谈方式」设为「离线演示 · 预设发言」，再开始对谈。这个模式展示预设发言，不会调用实时模型。

自动关系分析、观点建议和实时讨论整理需要可用的模型服务。仅启动页面不代表这些服务已接通。无实时分析结果时，不会仅凭星球距离猜测观点关系。

## OpenAI 兼容服务

在仓库根目录创建 `.env.local`，不要放进公开的 `web/` 目录。填入实际配置后重启服务。

```dotenv
AGENT_API_KEY=填写自己的密钥
AGENT_API_BASE=填写服务商的接口基础地址
AGENT_MODEL=填写账号可用的模型名
AGENT_DEFAULT_PROVIDER=compatible
```

服务端会在 `AGENT_API_BASE` 后拼接 `/chat/completions`。例如基础地址可以是 `https://api.deepseek.com`，也可以是兼容服务商要求的 `https://example.com/v1`。模型名以该账号实际可用的模型为准。

`.env.local` 只读取上述四个 `AGENT_*` 字段；进程环境变量优先。该文件被 Git 忽略，密钥只由服务端使用。远程兼容接口要求 HTTPS，本机 `localhost` / `127.0.0.1` 可使用 HTTP。

`AGENT_DEFAULT_PROVIDER=compatible` 让默认对谈、观点分析和讨论整理使用兼容服务。设为 `zhihu` 会指定知乎直答；未指定或为 `auto` 时，优先使用已配置的知乎凭证，其次才是兼容服务。没有凭证时返回未配置状态。

DeepSeek 域名使用非思考模式；结构化整理任务请求 JSON 输出。这是当前适配器行为，其他兼容服务也需要能够返回对应任务要求的结构。

## 知乎取材与直答

知乎服务使用独立的 `ZHIHU_ACCESS_SECRET` 环境变量，或由 `ZHIHU_SECRET_FILE` 指向的本机文本文件。未设置文件路径时，默认尝试 `/tmp/zhihu-probe/.secret`。

可以把凭证文件放在自己的私有目录，并在启动服务的同一终端指定路径。

```bash
export ZHIHU_SECRET_FILE=/绝对路径/到/你的知乎凭证文件
python3 web/server.py --port 8081
```

`ZHIHU_*` 不会从 `.env.local` 读取。文件中只保存自己的 Access Secret，不要把凭证文件提交到仓库。

知识星球中的「案例与来源 / 获取新观点」提供主动取材入口。每次取材最多两次上游请求，结果缓存 24 小时；刷新页面读取已有缓存，主动重新获取使用页面内的入口。缓存文件在已忽略的 `web/.data/` 下。

当前直答请求使用 `zhida-fast-1p5`，携带 `model`、`messages`、`stream` 参数。账号权限、额度与模型可用性以实际响应为准。代码中的接入方式可查看 [`zhihu_api.py`](../web/zhihu_api.py)，接口历史资料在 [知乎 API 调研记录](萝卜快跑_知乎API调研与案例接入_2026-09-11.md)。

来源策略保留原文优先。接口发现的未核对全文回答只在来源面板提供原文入口；已有原回答不被摘要覆盖。萝卜快跑材料限定为 2024 年历史讨论，其他内置话题也不是自动更新的实时热榜。

## 验证配置

先查看服务状态。

```bash
curl http://127.0.0.1:8081/api/agent/status
```

这个接口只说明是否配置、模型名和默认服务，不会证明账号余额或真实回复可用。接着在页面选择实时对谈，发起一轮请求，以实际回复判断服务是否可用。

实时分析和对谈会把参与任务的原文材料、用户输入及相关对话上下文发送给所选服务商。原作者材料始终是引用内容，Agent 发言不代表原答主本人。

| 现象 | 处理方式 |
| --- | --- |
| 提示未配置 | 确认 `.env.local` 在仓库根目录，四个字段已填，服务已重启 |
| 仍使用旧模型 | 检查启动终端是否设置了优先级更高的 `AGENT_*` 环境变量 |
| 密钥无效、余额不足、限流 | 按页面返回的原因检查服务商账号 |
| 超时或回复不完整 | 缩短补充条件后重试，检查所选模型是否适合短轮次对话 |
| 想先演示流程 | 手动选择「离线演示 · 预设发言」；实时失败不会自动伪装成成功回复 |
| 换端口后记录不见了 | 回到原来的协议、主机和端口读取并导出；`localhost` 与 `127.0.0.1` 也不同源 |

## 存储与检查

讨论和观点使用浏览器 `localStorage` 的 `gravity.sessions.v1`；故事进度使用独立的 `gravity.story.v1`。没有账户同步服务。原回答目录后续改变时，已经保存的讨论仍保留当时的来源快照。

单条讨论可导出 Markdown；个人历史可导出 JSON。浏览器阻止存储或空间不足时，页面会提示本机保存不可用，应及时导出。清理浏览器站点数据会清除对应的本地记录。

现有自动检查需要 Node.js 与 Python 3。

```bash
npm --prefix web test
PYTHONPYCACHEPREFIX=/tmp/zhihu-pycache python3 -m unittest discover -s web/tests -p 'test_*.py'
```

这些自动检查不能替代真实模型验收和实体手机性能测试。功能历史记录可从[仓库首页](../README.md#继续往里看)继续阅读。

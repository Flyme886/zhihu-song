# Gravity of Minds · 思想引力场

完整产品方案 v1.0 · 2026-09-11

> 在一张安静的画布上，放入自己的观点。与相似的思想结伴，带着同伴去碰撞不同的看法。

本文整合此前的产品讨论与视觉迭代。“已确认”指用户明确表达的要求；“建议”是为形成可执行方案补充的默认设计。接口能力、技术性能及尚未确认的玩法，不写成已验证结论。

## 1. 项目定位

**赛道：灵魂匹配局 · 社区 × 社交 × 知乎生态。**

思想引力场是一个以观点为交互对象的空间讨论产品。用户进入议题，将自己的想法放入画布，拖动观点球与其他球接触。同类观点结成二连球，再一起与不同观点展开讨论。

产品的第一层连接是思想之间的连接。人、知乎内容和 Agent 都可以提供观点，但用户在主界面只需要理解“小球代表一个观点”，无需学习不同对象分类。真人之间的持续联系可以在后续自然延伸。

用户预期获得三种收获：找到思想同伴；理解有价值的分歧；留下自己认可的讨论记录。它们是产品假设，需通过实际体验验证，不能直接宣称已经打破信息茧房。

## 3. 核心体验闭环

选择议题 → 放入观点 → 漫游画布 → 同类结伴 → 携伴碰撞异见 → 参与讨论 → 确认讨论收获 → 返回画布或保存记录。

首次体验应围绕一个完整闭环组织。界面不要求用户先理解质量、极性、向量、Agent 架构等概念。

首次进入：小球已经存在并轻缓漂浮，顶部显示当前议题，底部有“放入你的观点…”输入框。用户可先浏览，也可直接输入。只用一条短提示解释操作：“拖动小球，相似结伴，不同碰撞。”

建议首次放入观点后，附近出现一个容易理解的同类候选和一个不同视角，帮助用户完成第一次有效互动；这些候选应来自实际材料或明确的演示数据。

## 4. 页面与信息结构

### 4.1 默认页面：思想画布

画布覆盖绝大部分屏幕，不常驻辩论侧栏、日志面板或解释性卡片。

| 位置 | 内容与行为 |
| --- | --- |
| 左上角 | 小型标识与“思想引力场” |
| 顶部中间 | 当前议题，点击后打开议题选择层 |
| 右上角 | 个人入口与更多操作 |
| 画布区域 | 分散、轻缓漂浮的观点球，以及当前二连球 |
| 底部中间 | 小型输入框“放入你的观点…” |
| 右下角 | 缩放、重置视图；提供一键定位自己的球 |
| 左下角 | 首次操作提示，熟悉后弱化或消失 |

画布支持平移和缩放。桌面端悬停或聚焦显示一句摘要，点击查看详情，拖动自己的球或二连球发起交互。触屏端用轻点代替悬停，并提供“与它碰撞”的按钮入口。

默认只显示当前焦点及少量附近标签；其余观点通过交互展开，避免几十段文字同时占据画面。

### 4.2 观点详情

点击小球后，在球附近出现轻量详情层，展示观点摘要、主要理由和可展开的参考出处。关闭后立即回到画布。

来源透明放在详情层，不在主画布强迫用户辨认对象类型。引用的知乎文字与 AI 延展论述在详情内保持可区分，不把生成发言写成原作者亲口说过的话。

### 4.3 讨论状态

发起碰撞后，相关球靠拢至阅读区域，其他球轻微淡出并降低运动。按需展开一个简洁的讨论层，结束后收起，恢复画布。

长文本用可选择、可复制、可聚焦的常规界面承载。透明气泡承担探索，清晰文字承担阅读。

### 4.4 我的轨迹

记录我放入的观点、结伴、讨论、补充与修订。它是按需打开的个人记录，不常驻占据画布。

## 5. 观点球如何生成与表达

### 5.1 初始观点

建议从一个议题下取得的知乎内容中提炼若干有差异的观点，保留摘要、出处及时间。高赞可以帮助发现材料，但不等于论据可靠或观点全面；初始材料需要覆盖不同理由和条件。

**视觉数量必须与真实内容数量匹配。** 概念图中的约 40–60 个小球只表示理想密度，不代表接口一定提供足够独立观点。材料不足时减少可交互球数，不复制观点来伪装热闹，也不暗示这些球代表在线人数。

### 5.2 用户观点

用户输入短文后，系统提炼：核心主张、关注维度、主要理由、适用条件、尚不确定的部分。界面先展示短摘要，用户可纠正“这不是我的意思”。

小球生成时有即时视觉反馈；语义分析未完成期间可以浏览，但不能凭随机分类触发正式结伴或辩论。分析失败时保留原文，提供重试或直接阅读材料。

### 5.3 视觉参数

| 参数 | 建议含义 |
| --- | --- |
| 位置 | 共同关切和讨论关系的空间布局，不是真理坐标 |
| 颜色 | 当前议题的关注维度或轻量分组，不表示理性优劣 |
| 大小 | 保持窄范围差异；聚焦时略放大，不用于思想评分 |
| 细线 | 当前结伴关系，不默认把所有语义联系都画出来 |
| 微光或轮廓 | 选中、悬停、待确认等交互状态 |
| 透明度 | 层次与焦点管理，不代表观点可信度 |

建议不采用“论据越长球越大”“理性冷蓝、感性暖橙”“赞越多质量越大”等自动价值排序。

## 6. 核心玩法：同类结伴，异类交锋

### 6.1 关系判断

不能仅把立场压缩为支持与反对两个数值。系统需要结合主张、共同关切和适用条件，给出关系判断及简短理由。

| 关系 | 默认交互建议 |
| --- | --- |
| 主张接近且条件相容 | 提示结伴，形成二连球 |
| 关切相同、实现方式不同 | 提示存在共同点，也可以探索分歧 |
| 对同一问题有实质冲突 | 进入讨论入口 |
| 信息不足或不相关 | 轻触回弹，展示摘要，不强行结伴或对抗 |

用户可以纠正误判。短句表达不清、讽刺或有条件支持，都不应强行归为某一阵营。

### 6.2 二连球

两个观点接触后先轻微压缩、回弹，再建立柔软连接。保留两个独立球体和各自观点，不融合成一个巨球。

拖动一个球时，另一个带有轻微延迟地跟随；松手后短暂摆动，逐渐稳定。可以用细线与少量相对运动表现关系，不必永久画出明显轨道。

首版建议限制为二连球，支持解除和重新结伴。二连球接触第三个相近观点时显示补充或替换入口，不自动无限扩张。

若同伴只是对现有内容的观点代理，结伴形成的是观点关系；若涉及另一个真人的持续参与、代言或关系绑定，需要对方接受。这个区别在发生相关行为时说明，无需主画布增加对象分类。

### 6.3 携伴碰撞

双球一起靠近目标后，出现轻量目标提示。用户释放完成碰撞，短促柔和反馈后进入讨论。

双球的价值是带来互补理由与经验。默认由一位联合发言者汇总主张，同伴补充一个独立角度，对面获得同等回应机会。人数和球体数量不增加“正确性”分数。

拖动距离、速度和碰撞力度只影响视觉反馈，不决定观点胜负。

## 7. 辩论机制与人类参与

以下是建议默认流程，用户尚未最终确认。

### 7.1 三个短阶段

| 阶段 | 展示内容 | 用户参与 |
| --- | --- | --- |
| 说清楚 | 双方各用短段落表达主张和理由 | 修正 AI 对自己观点的理解 |
| 问关键 | 围绕一个核心分歧追问与回应 | 补充论据、提出问题、要求核实 |
| 留下来 | 整理共同点、仍然不同的地方、待验证问题 | 确认记录，选择继续或结束 |

三阶段不是固定六段自动播放。用户不插话时可以简短连续进行；用户插话时应停止当前生成，并把新输入纳入后续讨论。过长内容默认折叠。

一次讨论只深入一个关键问题。不要让 Agent 为了“高能交锋”制造互不相关的反驳。

### 7.2 Agent 的边界

Agent 根据用户已确认的观点和引用材料发言，可以提出建议，但不能悄悄替用户改变立场、承诺行动或宣告认输。

双方都可以承认信息不足。价值分歧不必被归纳为事实对错。不存在“必须握手言和”的最终回合。

模型同一次输出中扮演两边，可用作演示编排，但不能据此声称存在两个独立主体的真实社会互动。

### 7.3 示例

议题：“AI 应该批改学生作文吗？”

我的观点：“AI 可以让每个学生更快得到反馈。”

同伴：“教师批改负担很重，AI 可以承担基础检查。”

不同视角：“如果统一标准覆盖个性表达，学生可能越来越像在套模板。”

讨论聚焦：“哪些反馈适合自动化，哪些判断应由教师保留？”

可能沉淀：“对语法检查和及时反馈存在共同点；对审美评价、个性表达和最终评分仍需明确边界。”这只是示例，不是对该议题的事实裁决。

## 8. 轻盈、柔和、灵动的视觉与动效

### 8.1 已确认的画面骨架

干净背景、许多小球、少量必要控件。视觉重心在球与球的关系，不在标题、背景视频或常驻卡片。

MotionSites 的参考价值是构图的克制、材质的完成度和交互的连贯性。此前已经确认，不能直接把案例中的 Hero 大字和电影布景移植成这个产品的主页面。

### 8.2 最新材质方向：薄透气泡

这是根据“不够轻盈”的反馈提出的候选方向，尚未最终定稿。

- 球体内部大部分透出背景，只留非常轻的色彩和边缘变化。
- 避免实心填充、深色下半球、硬质高光、明显落地阴影。
- 使用低饱和蓝、绿、淡紫、浅杏等颜色，具体颜色与主题维度的对应需要稳定。
- 通过薄轮廓和极小高光保持可辨认性，不把所有球做成完全不可见的透明圆。
- 当前球、同伴和目标略增强轮廓，其余保持克制。

轻盈与可用性需要一起验收。视觉上很淡的小球，实际命中范围可更大；悬停、聚焦和触屏选中时需要足够清晰的反馈。不能仅用颜色传达关系。

### 8.3 动效建议

| 行为 | 期望手感 |
| --- | --- |
| 静置 | 各球不同相位地缓慢漂移，偶有停顿，不整齐上下摆动 |
| 接近 | 轻微响应，不出现强磁吸与不可控抖动 |
| 悬停或聚焦 | 球略微清晰、略放大；摘要淡入 |
| 拖动 | 主球立即跟手，形变极小；位置反馈不等待网络 |
| 同伴跟随 | 细线轻弯，同伴略延迟，松手后迅速稳定 |
| 同类接触 | 柔软压缩、回弹、结伴 |
| 异类接触 | 局部短促波纹，再展开讨论层 |
| 阅读 | 周边减速或暂停，避免文字追着球移动 |
| 返回画布 | 恢复原焦点与位置，不让用户迷失 |

初始调参参考：常规反馈约 150–250ms，关系建立约 300–500ms，静置漂移约 6–12 秒一个缓慢周期。均是待原型实测的起点，不是已验证最佳值。

建议提供减少动态效果设置与键盘操作；音效默认克制、可关闭，避免持续碰撞声。无全屏震颤、长拖尾、大量火花或夸张爆炸。

## 9. 自然漂移与偶发互动

背景运动负责生命感，不应悄悄替用户发起正式辩论。

自然接近可以短暂显示双方各一句摘要或一个共同关键词，随后恢复安静。设定频率限制，同一对球不会反复刷提示。

正式结伴、正式碰撞与记录由明确用户操作触发。装饰层的每次接触不调用模型。讨论中的个人观点修订也不由物理漂移自动发生。

思想日志建议收进“我的轨迹”，不保留原案右侧自动滚动的常驻信息流。

## 10. 讨论结晶与复盘

### 10.1 首版结晶

每次讨论后生成一份简短记录：议题与参与观点；共同关切；关键分歧；相关材料；我补充或修改了什么；仍待验证的问题。

用户可以保持原观点。“理解对方但仍不同意”是有效结果。任何“我改变了什么”的表述都应由用户确认后保存。

分享卡采用简洁排版，展示用户认可的内容，不输出“偏见减少30%”等没有测量依据的数值。

### 10.2 后续复盘

如果以后做时间轴，应按真实保存的观点版本、讨论和新材料记录回放。视觉位置变化与语义变化分别记录，不能把拖动轨迹解释成思想变化。

事实整理使用“有来源支持的陈述”“仍有争议”“信息不足”这样的表达，附出处与时间，不使用“无可争议的核心事实”作为模型的自动裁决。

不预设热点一定经历谣言、反转、通报、终局，也不预设群体一定从极化走向理性。没有历史数据时，只回放本次会话。

### 10.3 原案扩展功能的安排

| 功能 | 当前建议 |
| --- | --- |
| 破茧透镜 | 后续可做；先以“看看不同视角”入口验证价值 |
| 自动微碰撞弹幕 | 弱化，低频且可关闭 |
| 三维认知水晶与全场坍缩 | 暂不进入首版，优先保证极简与轻盈 |
| 哲理小说、热点终局故事 | 可选创作出口，不作为主闭环依赖 |
| 关注创作者卫星轨道 | 接口能力和需求明确后再加入 |
| 全群体历史回放 | 需要真实持续采样及版本记录，后续建设 |

以上是范围收敛建议，不代表用户已经决定永久删除这些功能。

## 11. 知乎生态与接口策略

此前未成功取得并验证官方接口包完整正文。下列接口名称、配额与用途来自原始提案，正式开发前需要逐项确认，不能视作已验证 API 契约。

| 能力 | 产品用途 | 开发前需要确认 |
| --- | --- | --- |
| 热榜，原案称 hot_list | 选择当前议题 | 路径、鉴权、字段、刷新频次与配额 |
| 搜索，原案称 zhihu_search | 找到不同观点与参考材料 | 是否返回全文、摘要、评论、作者、链接及分页 |
| 直答，原案称 chat/completions | 观点提炼、关系解释、讨论编排 | 模型能力、流式输出、结构化结果、工具支持与配额 |
| 故事能力 | 可选讨论纪念创作 | 是检索还是生成、是否支持自定义输入；未核实前不依赖 |
| 关注流，原案称 feed/following | 后续个性化入口 | 是否开放、用户授权与可返回信息 |

最小闭环只依赖可用的议题与内容来源，以及可用的文本分析/生成能力。是否允许补充其他模型，以比赛规则、账号能力和用户预算为准。

真实内容不足时可使用明确标注的演示议题和预置材料；不能把旧材料、样例发言或离线脚本伪装为实时知乎结果。

## 12. 配额、等待与降级

原案给出的热榜100次/日、直答100次/日、搜索1000次/日均待核实。

仅作容量示例：若直答每天100次，每位用户提炼观点1次、讨论3次、复盘1次，共5次，则理论上最多20次完整会话，尚未扣除初始化、失败重试与继续追问。一次请求输出全部讨论虽然节省调用，但难以真实响应中途插话。

建议由服务端统一管理配额、缓存和进行中的请求；浏览器缓存只改善本机体验，不能替代全局限额控制。鉴权密钥保留在服务端。

| 场景 | 处理方式 |
| --- | --- |
| 多人进入同一议题 | 复用近期的议题材料与初始观点，避免重复取数 |
| 语义关系已知 | 复用关系结果，但允许用户纠正 |
| 新材料或观点已修改 | 按内容版本失效缓存，重新分析 |
| 普通漂移和装饰碰撞 | 本地计算，不调用模型 |
| 生成较慢 | 球体立即响应，文字显示真实生成状态；支持取消 |
| 用户中途插话 | 停止或废弃旧输出，基于新会话版本继续 |
| API不可用 | 保留输入和已有材料，明确提示；可切换演示模式 |
| 相似历史讨论 | 复用证据与结构，直接重播时明确标为历史示例 |

离线演示应单独标注模式和数据时间。可以演示拖动、结伴、已存讨论与回放，但不能声称离线时完成了实时检索或生成。

## 13. 技术架构建议

本节是实施建议，不是已有系统说明。首版选择一套简洁架构，避免把多种渲染与动效库全部叠加。

- **界面层：React + TypeScript。** 承载输入、文字阅读、详情与设置；可使用 Vite 建立单页应用。
- **画布层：优先评估 PixiJS。** 绘制小球、细线与局部反馈。若少量 Canvas 2D 绘制已满足质感和性能，也无需强行增加复杂度。
- **运动层：受控的简化弹簧与阻尼。** 处理缓慢漂浮、边界、轻碰撞、二连球约束。语义决定关系，物理只表现关系，不做思想正确性模拟。
- **过渡层：Motion 或少量原生动画。** 管理文字与面板；Canvas球变为界面元素时需要屏幕坐标衔接，不能只靠 layoutId 自动完成。
- **服务层：API代理与会话编排。** 处理鉴权、配额、来源材料、缓存、生成任务与中断。
- **持久化：关系数据和事件记录。** 首版存储观点、材料引用、结伴、讨论、用户确认的修订，具体数据库随部署环境确定。

数据顺序：获取议题材料 → 提炼与校验初始观点 → 建立可解释的关系 → 在画布显示 → 用户交互 → 讨论编排 → 保存用户确认的记录。

语义状态、画布位置和界面状态分离。拖动小球不会修改立场；模型返回新观点也不能让整个画布突然重排。

动画每帧不驱动全量 React 更新。限制高像素比、滤镜面积与动态文本重绘；切后台暂停运动。首版从约30–60个有内容的小球起步，性能是否足够以目标设备实测为准，不承诺普遍达到120FPS。

## 14. 最小数据模型

| 对象 | 最少需要保存的信息 |
| --- | --- |
| Topic 议题 | ID、标题、来源、材料获取时间 |
| Evidence 材料 | ID、出处、原文或摘要、时间、可用性 |
| Thought 观点 | 原文、确认后的摘要、主张、理由、条件、证据ID、版本 |
| Relation 关系 | 两个观点ID、关系说明、置信状态、用户纠正 |
| Pair 结伴 | 两个观点ID、建立及解除时间、必要的参与确认 |
| Discussion 讨论 | 观点版本、回合、用户输入、引用、生成状态、未决问题 |
| Revision 修订 | 修改前后内容、原因、用户确认、时间 |
| CanvasState 画布 | 位置、相机、焦点；不作为认知变化证据 |
| Event 事件 | 会话内发生了什么、顺序、时间、关联对象 |

## 15. 首版范围与后续范围

### 建议首版必须完成

1. 一个经过材料校验的完整演示议题，以及可扩展的议题选择入口。
2. 干净、可平移缩放的观点画布；材质最终定稿。
3. 输入观点、纠正摘要、生成自己的球。
4. 浏览其他观点与来源。
5. 同类二连球、解除、拖动跟随。
6. 与异见球碰撞，完成一次简短讨论。
7. 用户插话、纠正和停止生成。
8. 保存用户确认的讨论结晶与个人轨迹。
9. 服务端配额控制及明确的演示降级。

### 后续再投入

真人实时协作与邀请、更多人结伴、离线代言、跨议题匹配、破茧透镜、长时间群体演化、故事创作、3D水晶、复杂社交关系与创作者关注轨道。

如果缺少多人服务，首版可以是单用户探索内容观点并由 Agent 编排讨论的产品。展示时如实说明，不以球数量暗示真人社区已经形成。

## 16. 实施顺序与验收

团队人数与截止时间尚未提供，采用里程碑而非虚构日期。

| 里程碑 | 交付物 | 通过条件 |
| --- | --- | --- |
| M1 视觉与手感 | 可交互画布、气泡候选材质、二连球跟随 | 用户确认材质有轻盈感；拖动跟手，球可辨认 |
| M2 数据接入 | 一个真实议题、可追溯观点材料 | 确认接口与配额，逐条能回到出处 |
| M3 语义与结伴 | 观点提炼、关系说明、二连球机制 | 不相关观点不强行碰撞，误判可纠正 |
| M4 讨论闭环 | 短讨论、人类插话、结晶保存 | 新输入确实影响后续，引用可查，不强迫共识 |
| M5 演示与完善 | 现场流程、错误处理、降级 | 正常与断网演示都不丢用户输入，模式清楚 |

建议性能目标：约50个小球在指定演示设备上稳定接近60FPS；拖动反馈在下一绘制帧响应；文字阅读时稳定；低性能设备可以减少节点与动态。目标设备、屏幕分辨率与浏览器应写进实际验收记录。

重点验证四类风险：透明球是否难以选中；自动关系是否误读用户；插话后是否继续输出旧回复；缓存和离线结果是否被误认为新生成。

产品效果不以“改变多少人的立场”为目标。先观察用户能否无讲解完成首次结伴、是否能说清一个新理解的分歧、是否愿意继续探索或保存记录。

## 17. 黑客松演示建议

下面是一段约三分钟的建议脚本，可按实际展示时长缩放。

| 时间 | 展示 |
| --- | --- |
| 0:00–0:20 | 进入干净画布，球轻缓漂浮，用一句话说明“相似结伴，不同碰撞” |
| 0:20–0:45 | 输入观点，确认摘要，自己的球出现 |
| 0:45–1:10 | 拖向同类，二连球建立；拖动展示同伴的柔软跟随 |
| 1:10–1:50 | 携伴碰撞异见，讨论聚焦一个实际分歧 |
| 1:50–2:20 | 用户插入一个条件，后续回复相应改变 |
| 2:20–2:45 | 展示共同点、分歧和有出处的材料，确认个人记录 |
| 2:45–3:00 | 返回画布，说明下一次探索如何继续 |

最有说服力的展示点是：动作直观；同伴增加了有效角度；用户能够影响讨论；结晶可解释且有出处。视觉震撼服务于这条体验链。

## 18. 产品说明口径

**一句话：思想引力场，让相似的观点结伴，让不同的观点对话。**

简短介绍：我们把一场讨论展开成一张可以触碰的思想画布。每个小球承载一个观点，用户可以拖动自己的球，与相近观点组成二连球，再一起接近不同的看法。AI帮助组织材料与交锋，用户随时补充和纠正，最后留下自己认可的理解与分歧。

不使用未经验证的宣称：自动识别思想深度、量化减少偏见、证明群体走向理性、所有设备稳定120FPS、已经拥有真实在线社交生态。

## 19. 下一步待定事项

这些问题不阻止方案成形，但会影响实现。当前建议先完成M1，用真实拖动和漂浮验证轻盈感，再锁定材质。

1. 薄透气泡是否最终满足审美，浅色是否作为首发主题。
2. 辩论过程中用户希望投入多少操作，是否接受本文的三阶段短讨论。
3. 真人之间是否在首版建立关系；若需要，如何邀请和接受。
4. 哪些知乎接口已经可用、实际配额以及其他模型的可用范围。
5. 开发人数、期限、演示设备、展示时长和预算。

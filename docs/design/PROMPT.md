我在做一个知乎黑客松参赛项目《和不同》，要你构建它的主界面。四份附件：`BRIEF.md`（构建任务书，冲突以它为准）、`model.ts`（数据契约与结算规则）、`mock-topic.json`（占位数据，用来渲染）、`prototype/index.html`（已定稿的样式基底，只有 CSS 没有 body）。

## 它是什么

一局卡牌。用户坐在知乎答主的位置上：三个人来问同一件事，手里有四张真实高赞回答做成的卡，**卡不够分，必须弃掉一张**。指派完点结算，每张卡在每个人身上会得到三种结果之一：生效 / 无效 / 反噬。

**同一张卡，三个人三种结果；同一张卡，两个年代两种结果。**

它不是卡牌对战游戏。卡牌游戏的语法以赢为中心，而这个产品的论点是没有人赢 —— 所以没有分数、没有排行榜、没有血条，结尾是复盘不是结算得分。

## 首轮范围

只做 `BRIEF.md` §4.1 ~ §4.5：卡、提问者卡、配卡与弃牌、共享轴、结算三态。**§4.6 卡失效回调、§4.7 复盘地图、§4.8 结局卡这轮不做**，留占位即可。

一个节点，`mock-topic.json` 的数据。不要路由、不要多议题切换、不要设置页。

## 四条不可动摇的规则

**1. 结算是确定的，不是随机的。** 判定就三行：`requires ⊆ has` → 生效；`requires ⊄ has` 且 `strains ∩ lacks = ∅` → 无效；`requires ⊄ has` 且 `strains ∩ lacks ≠ ∅` → 反噬。同一组配卡跑两遍必须完全一样，**不许有任何随机数参与判定**。意外感来自提问者藏着的能力缺口（`has` / `lacks` 结算前不可见，也不能出现在 DOM 里），不来自骰子。凡是让人联想到抽奖、转盘、概率的视觉语言全部禁止。唯一允许随机的地方是叙述文本的选择：每格备了 4~5 条 `narration`，运行时随机取一条，只影响措辞不影响结果。

**2. 三种结果靠语气分，不靠好坏分。** 生效 = 暖褐 `#B06E28`，落定、安静。无效 = 中性灰，不下沉、不打叉 ——「没接上」不是「错了」。反噬 = 赭色 `#A8642A` 描边收紧，**要有一个可感的顿挫**，但不许是爆炸、不许是红色警告。禁止红/绿、✓/✗、置灰。反噬的情绪是「我没想到这句话会这样落地」，不是「我输了」。

**3. 卡面的「如果」那一句是必填槽位，且只能来自答主原文自述。** 三档来源徽章全站强制出现：`答主原文自述` / `人工校验` / `AI 推测`。最高档是答主自己在回答里写明的适用范围，可点进原帖核对，视觉权重最高。这个格式就是整个设计的论点 —— 散文可以省掉前提，省掉了还显得更有力，所以高赞回答系统性地省；卡牌逼着把前提填进一个必填的槽位。

**4. 卡是真的，提问者是虚构的。** 三个提问者是我们捏的角色，UI 必须**在用户问之前就主动说明**，不能藏在关于页里。数据层有 `is_fictional: true`，读到就渲染标识。反过来卡面每句话都可点回原帖。这两件事要在同一屏里同时成立。

## 视觉

**深色牌桌**。用户坐在桌前玩一局，不是在读一份文档。参照 `prototype/style-compare.html`（已定稿的风格草图）。

牌桌底色 `#2A2520`（深棕不是纯黑），卡面用亮色纸 `#FAF7F0` 浮在桌上。暖金 `#C8A55A` 用于提示和高亮。三个提问者各有一个色系的头像圆圈（暖橙 / 青绿 / 紫灰）。完整色板在 BRIEF §5。

衬线体用于卡面条件句和引文，无衬线用于界面，数字一律 `tabular-nums`。

**游戏质感不来自特效**，按这个顺序投入：发牌与落位的手感（翻牌、吸附、回弹）→ 三格依次揭示的节奏（不要同时出，反噬那格留停顿）→ 卡面本身的质感（卡头黑底白字、卡角、卡边，像一张能捏起来的卡）→ 转场。第一条做好了就够了。

**明确不要**：紫蓝渐变、玻璃拟态、霓虹、发光边框、大圆角堆叠、装饰性 emoji、Hero 区、营销文案、抽奖转盘、血条、分数、排行榜、稀有度光效。浅色模式也不做。

品味目标是**一局做工严谨的桌游**，不是 AI 产品页，也不是手游抽卡界面。使用场景只有两个极端：投影仪上 3 米外能读卡面，和手机竖屏。没有中间态。

## 两个我特别在意的细节

**必须弃满一张才能结算。** 弃牌区是独立的一块，不是「剩下的那张」。稀缺是这个产品的机制核心 —— 它把问题从「哪张卡最好」换成「这张卡适合谁」。不要给「可以不弃」的绕路。弃掉的卡要记住，后面复盘屏会回调它。

**反噬那一下是全产品最高光的时刻。** 三格依次揭示，反噬格要留停顿，然后揭示结算前没告诉过用户的那件事（`reveal`：这个人缺什么），压上定版文案：

> 这条建议没写错。它只是不是写给他的。

这句不要改写成更软或更狠的版本。

## 技术

React + Tailwind（项目最终是 Next.js）。**运行时不调任何 API、不调 AI**，结算是纯函数。叙述文本全部预置在数据里。

拖拽是这里最大的无障碍风险 —— v2.0 用的原生 `<input type=range>` 天然键盘可达，拖拽卡片不是。**必须提供等价的非拖拽路径**：优先给每张卡配一个「给谁」的原生 `<select>`（省事也更稳），弃牌同样要有键盘路径。结算结果用 `aria-live="polite"` 播报，包括三格的结果与解释。

`prefers-reduced-motion` 下吸附回弹取消，**但依次揭示的节奏保留**（时长压到 40%）—— 揭示顺序承载语义，不能一次全出。

## 文案纪律

只能说「生效 / 无效 / 反噬」，不能说「成功 / 失败 / 对 / 错」。只能说「这条建议在他身上不成立」，不能说「这条建议是错的」。只能说「本模型中的适用度」，不能说「概率 73%」「正确率」。卡过期时只能说「攻略没写错，是版本变了」，不能说「打脸」「幻觉」「落后」「过时」。

答主是**卡牌设计师，不是卡** —— 可以说这张卡在当前版本很弱，不能说答主错了。答主是知乎的核心资产，不是素材。

## 交付

先给我一个节点能跑通的版本：发牌 → 指派 → 弃一张 → 结算三态。发牌手感和反噬那一下是最难的部分，值得单独过一轮，我确认了再往下做卡失效回调和复盘屏。

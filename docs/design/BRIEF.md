# 和不同 · 前端构建任务书

> v3.0（卡牌局版）。完整产品需求见 [PRD.md](../../PRD.md)；本文只留与界面有关的部分，已剔除赛事、配额、运营内容。
> ⚠️ 与 PRD 冲突处以本文为准。目前只有一处：§4.4 用共享轴取代双百分比，且该轴只在复盘屏出现。
> v2.0 的滑杆仪器已废止。它的**样式基底、条件地图几何与求解器全部保留**，只是从主界面降级成复盘屏的一块只读视图。

## 0. 一句话

你坐在答主的位置上。三个人来问你同一件事，你手里有四张真实知乎高赞回答做成的卡 —— 卡不够分，你得决定哪句话给谁，哪句话不说。

记忆点：**同一张卡，三个人三种结果；同一张卡，两个年代两种结果。**

## 1. 这不是什么

不是落地页、不是仪表盘、不是聊天界面、不是性格测试。**没有 Hero、没有 CTA、没有营销段落**，第一屏就是发牌。

也不是卡牌**对战**游戏。卡牌游戏的语法以赢为中心，而这个产品的论点是没有人赢。所以：

- 结果只有 **生效 / 无效 / 反噬**，没有成功失败，没有分数，没有排行榜
- 结尾是**复盘**，不是结算得分
- 不做血条、不做回合计时、不做「你击败了 87% 的玩家」

用户全程只做一个动作：**把卡指派给人**。界面其余部分都是这个动作的后果。

使用场景是两个极端，没有中间态：

- **投影演示** —— 3 米外能读卡面。浅底深墨，不能靠低对比的细字表达层次
- **手机分享链接** —— 竖屏单列，卡要能一张一张竖着翻

## 2. 四条不可动摇的规则

违反任意一条，产品就退化成一个抽卡小游戏。

### 2.1 结算是确定的，不是随机的 ★ 最重要

判定规则三行，全部可预演，**不许有任何随机数参与判定**：

| 条件 | 结果 |
| :--- | :--- |
| `requires ⊆ has` | **生效** |
| `requires ⊄ has` 且 `strains ∩ lacks = ∅` | **无效** |
| `requires ⊄ has` 且 `strains ∩ lacks ≠ ∅` | **反噬** |

同一组配卡跑两遍必须完全一样。意外感来自**提问者藏着的能力缺口**（`has` / `lacks` 结算前不可见），不来自骰子。

这个区别是产品的命门：随机结果教给用户的是「命不好」，条件驱动的结果教给用户的是「同一句话对不同人后果不同」。UI 上凡是让人联想到抽奖、转盘、概率的视觉语言全部禁止。

唯一允许随机的地方是**叙述文本的选择**：每格备了 4~5 条 `narration`，运行时随机取一条，只影响措辞，不影响 `outcome`。

### 2.2 三种结果靠语气分，不靠好坏分

沿用色温逻辑，禁止红/绿、✓/✗、置灰：

| 结果 | 语气 | 视觉 |
| :--- | :--- | :--- |
| 生效 | 落定 | 暖褐 `#B06E28`，轻微升起，安静 |
| 无效 | 空转 | 中性灰 `.t3` 的近亲，不下沉、不打叉 —— 「没接上」不是「错了」 |
| 反噬 | ★ 「啊?」 | 赭色 `#A8642A` 描边收紧一下，**要有一个可感的顿挫**，但不许是爆炸、不许是红色警告 |

反噬是全产品最高光的那一下（见 §4.5）。它的情绪是「我没想到这句话会这样落地」，不是「我输了」。

### 2.3 每张卡、每个条件都必须挂来源

三档来源徽章，全站强制出现，不允许有裸引文：

| tier | 中文 | 含义 | 徽章色 |
| :--- | :--- | :--- | :--- |
| `author_stated` | 答主原文自述 | 答主自己在回答里写明的适用范围（「前提是…」「只适合…」），**必须可点进原帖核对** | 暖褐 `.t1` |
| `human_verified` | 人工校验 | 我们逐字核对原文后判定 | 冷绿 `.t2` |
| `ai_inferred` | AI 推测 | 模型推的，必须显式标注 | 中性灰 `.t3` |

**卡面「如果……」那一句只能来自 `author_stated`。** 别的档位可以出现在卡的补充信息里，但不能占那个槽位 —— 那句话是整个产品的可信度所在。

### 2.4 卡是真的，提问者是虚构的

三个提问者是我们捏的角色。UI **必须在用户问之前就主动说明**，不能藏在关于页里。数据层用 `is_fictional: true` 强制打标，组件读到这个标记就渲染标识。

反过来，卡面每句话都可点回原帖。这两件事要在同一屏里同时成立，用户才会信任前者、也不会误认后者。

## 4. 组件清单

按构建顺序。**第一轮只做 §4.1 ~ §4.5**，§4.6、§4.7 留占位。

### 4.1 卡（最核心）

卡面结构，从上到下：

| 槽位 | 内容 | 说明 |
| :--- | :--- | :--- |
| 标题 | `headline` | 一行，是这张卡的主张 |
| ★ 条件句 | `如果 <quote> 就 …` | **必填槽位**，逐字引文，来源必须是 `author_stated` |
| 来源徽章 | `✓ 答主原文自述` | 可点，跳原帖锚点 |
| 出处 | 答主 / 时间 / 赞数 | 小字，一行 |
| 版本号 | `2016 版` | 过期卡额外标（见 §4.6） |

**条件句是卡的主体，不是附属。** 用衬线体、大行距，按「值得读」排版。这个格式是整个设计的论点：散文可以省掉前提，省掉了还显得更有力，所以高赞回答系统性地省；卡牌逼着把前提填进一个必填的槽位。我们只做了一件事，把它印回卡面上。

翻牌、落位、指派吸附要有手感 —— **游戏质感的下限就在这里**，不在特效上。

### 4.2 提问者卡

只显示 `visible[]`（年级 / 住校与否 / 一句自述）。`has` / `lacks` **结算前绝不可见**，包括不能出现在 DOM 里 —— 会被扒。

必须带虚构标识（§2.4）。标识要素朴，别做成免责声明的字号。

### 4.3 配卡区与弃牌区

- 拖拽指派，落点吸附，可反复调整直到点结算
- 弃牌区独立，**必须弃满一张**才解锁结算按钮
- 弃掉的卡要记住并传给复盘屏
- 触摸目标 ≥ 44px；手机端卡可竖向单列滚动
- 需要一个**一键重置本节点**按钮（现场救命用）

### 4.4 共享轴游标 ★ 对 PRD 的有意修改

PRD 画的是两个百分比（A 62% / B 38%）。**改成一条共享横轴 + 单个游标**：左端 A、右端 B、中点是分水岭。

理由：两个百分比会被读成概率，这是明令禁止的措辞。一条轴上的一个游标在结构上无法被这样误读 —— 它只表达「更靠近哪一侧」。

轴下方固定一行小字：`这不是概率，也不是正确率`。

**只在复盘屏出现。** 配卡与结算阶段不给任何数值读数 —— 那会把注意力从「这张卡适合谁」拉回「哪张卡分高」。

### 4.5 结算三态

三格依次揭示，每格含：`outcome` 徽章 / 从 `narration[]` 随机取的一条叙述 / `because` 一行解释 / 反噬时额外揭示 `reveal`。

三套动效，按 §2.2 的语气分。**反噬要有一个可感的顿挫**：

> 这条建议没写错。它只是不是写给他的。

这句是定版文案，压在反噬格里。不要改写成更软或更狠的版本。

### 4.6 卡失效回调

进入下一个节点时触发。要同时呈现三件事：

1. 卡面**一个字没改**（原样再放一次）
2. 赞数**还在涨**（新旧数字并列）
3. 它依赖的条件**已经没了**（`now_invalid_because` + `basis_refs` 可点）

配文案：**「攻略没写错，是版本变了。」** 过期卡标版本号（`2016 版`）。

⚠️ 禁用「落后」「过时」「打脸」。答主是卡牌设计师，不是卡 —— 可以说这张卡在当前版本很弱，不能说答主错了。

### 4.7 复盘屏条件地图（只读）

模型与几何**全部复用** `prototype/index.html`：`Dua` / `Dof` / `shiftAt` / `solveA` / `curve` / `smooth` / `CL`。改动只有两条：去掉滑杆、加上按年份自动播放。

| 图层 | 画法 |
| :--- | :--- |
| 适用区底色 | A 侧 / B 侧各铺一层**极浅**色温底。不要实心色块 |
| 分水岭 | 全图唯一的强曲线，2px 赭色 `#A8642A`，`D = 0` 等值线 |
| 提问者 | 三个点，固定。小满**刻意放在脊线附近** |
| 真实回答 | 8~12 个空心小圆，固定点。年份推进时**它们不动，分水岭扫过它们** |
| 被扫过的点 | 只改描边状态。不要打叉、不要变灰、不要写「已失效」 |

等值线在固定 x 栅格上求解、点数恒定，所以前后两条 SVG `path` 的 `d` 结构一致，可直接 `transition: d 950ms`，不需要逐帧 JS 插值。

`watershedPath()` 返回的不只是 path，还有 `inRange: boolean[]`（每个采样点是否真的解出了 `D = 0`）和 `clipped`（连续出图区间）。`false` 段的意思是「这一整列都在某一侧的适用区域内」—— 是真信息，不是求解失败。这些点仍留在 path 里（点数必须恒定），渲染时**虚化**：主曲线正常画，出图段叠一条 1px、`opacity .28`、`4 3` 虚线盖住。照旧实线画会得到一条贴着地图边缘的直线，看上去像 bug。

留白优先。宁可像地形图，不要像热力图。

配文案：**「十年里分水岭扫过了小满，没扫过小雨。」**

### 4.8 结局卡

打法类型（条件派 / 从众派 / 稳妥派 / 激进派）由**配卡逻辑反推**，不是开场自评 —— 从打法算出来的标签比自我报告的更站得住。附一行依据（「三个节点里你有 5 次先看人再挑卡」）。

出图用 `html-to-image`（Satori 因中日韩字体与换行坑已排除）。图上必须带「提问者是虚构的」—— 素材离开产品页之后，这句说明只能靠图自己带着走。

## 5. 视觉

**整体是深色牌桌**，用户坐在桌前玩一局。桌子摆在一间冷灰的屋子里，
桌面是近黑的冷灰，卡是白的，红是唯一的强调色。

### 色板

单一事实来源是 `web/src/app/globals.css` 的 `@theme` 块 —— 下表是它的说明，
改色先改那里。`prototype/style-compare.html` 是暖棕金的初版草图，**已被这版取代**，
只作为历史留着，冲突时以本表和 `globals.css` 为准。

| 用途 | 色值 | 说明 |
| :--- | :--- | :--- |
| 画面最底 | `#08090B` | 桌子之外的空间 |
| 牌桌外框 | `#0D0E11` | 近黑冷灰，不是纯黑 |
| 桌心 | `#14161A` | 卡片区、提问者区背景 |
| 桌后墙面 | `#C8CCD2` | 冷白灰，一面墙 + 两侧板缝 |
| 卡面 | `#FBFBFC` | 中性白纸，与桌面形成反差 |
| 墨色 | `#14161A` | 卡面文字 |
| 正红 | `#D0202C` | 主操作、落点命中、当前提问者、反噬。**唯一的强调色** |
| 暗红 | `#8F1A22` | 卡面年份、票数、细红线。存在但不喊 |
| 钢白 | `#CFD6DE` | 刻线、准线、界面描边 |
| 冷白（生效） | `#D8E2EC` | 落定、干净 |
| 中性灰（无效） | `#6F7680` | 不下沉，不打叉 |
| 正红（反噬） | `#D0202C` | 描边收紧，有顿挫 |
| 辅助灰 | `#7D848E` | 说明文字、脚注 |
| 微光 | `rgba(207,214,222,.19)` | 边框、分隔线、hover 状态 |

**为什么从暖棕金换成冷黑白红。** 唯一的硬指标是「投影仪上 3 米外能读卡面」。
赭色 `#A8642A` 压在深棕 `#2A2520` 上只有 3.4:1，暖金刻线压在暖桌上更低 ——
投影仪再吃掉一半对比度，现场就是一片糊的暖褐色，三态分不出来。
换成冷板 + 正红之后，同样的层级关系拿到大约两倍的对比度
（生效那枚筹码从 4.4:1 涨到 13.8:1），而且红只占很小的面积，越冷越跳。

- 衬线（Songti SC / Noto Serif SC）用于引文、卡面条件句、反噬揭示文案
- 无衬线（PingFang SC）用于界面
- 数字全部 `font-variant-numeric: tabular-nums`
- 卡面是亮色纸（`#FBFBFC`），浮在深色桌面上 —— 卡要像一张实物
- 三个提问者的头像圆圈统一用红，靠**亮度**分开（正红 / 暗红 / 深红），不靠色相。
  引进第二、第三个色相，红就不是唯一重音了

### 游戏质感来自哪里

不是来自特效。按这个顺序投入：

1. **发牌与落位的手感** —— 翻牌、吸附、回弹。这一条做好了就够了
2. **依次揭示的节奏** —— 三格不要同时出，反噬那格留停顿
3. **卡面本身的质感** —— 卡角、卡边、卡头黑底白字。像一张能捏起来的卡
4. 转场（配卡 → 结算 → 下个节点）

### 明确不要

紫蓝渐变 · 玻璃拟态 · 霓虹 · 发光边框 · 大圆角堆叠 · 装饰性 emoji · 无意义图标 · Hero 区 · 营销文案 · 抽奖转盘 · 血条 · 分数 · 排行榜 · 稀有度光效。浅色模式也不做 —— 牌桌就是深的。

品味目标：**像一局做工严谨的桌游**，不是 AI 产品页，也不是手游抽卡界面。使用场景只有两个极端：投影仪上 3 米外能读卡面，和手机竖屏。

## 6. 文案纪律（硬约束，前端也要遵守）

| 只能说 | 不能说 |
| :--- | :--- |
| 生效 / 无效 / 反噬 | 成功 / 失败 / 对 / 错 |
| 这条建议在他身上不成立 | 这条建议是错的 |
| 当前条件下更接近某篇回答的适用区域 | 这就是正确答案 |
| 本模型中的适用度 / 影响贡献 | 概率 73% / 正确率 / 因果效应 |
| 攻略没写错，是版本变了 | 打脸 / 幻觉 / 落后 / 过时 |

答主是知乎的核心资产，不是素材。全站不出现贬损答主的表述。

## 7. 响应式

| 断点 | 布局 |
| :--- | :--- |
| ≥ 861px | 提问者一行三列，手牌一行四列 |
| 601~860px | 提问者一行三列（缩小），手牌两行两列 |
| ≤ 600px | 全部竖向单列，卡一张一张翻；复盘屏地图退化成静态图 + 文字摘要 |

手机端优先保证**卡面条件句可读** —— 那一句读不到，这个产品就没有内容。

## 8. 无障碍

拖拽是这里最大的无障碍风险：v2.0 的原生 `<input type=range>` 天然键盘可达，拖拽卡片不是。所以**必须提供等价的非拖拽路径**：

- 每张卡可聚焦，`Enter` 拾起 → 方向键在三个提问者间移动 → `Enter` 落下，`Esc` 取消
- 或每张卡配一个「给谁」的原生 `<select>`（更省事，也更稳，优先这个）
- 弃牌同样要有键盘路径
- 结算结果用 `aria-live="polite"` 播报，包括三格的 `outcome` 与 `because`
- 复盘屏地图配屏幕外等价文字
- 焦点环 2px 实线

`prefers-reduced-motion` 下：吸附回弹取消，**但依次揭示的节奏保留**（时长压到原来的 40%）—— 揭示顺序承载语义，不能一次全出。

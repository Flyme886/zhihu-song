# 思想引力场：演示 API 接入验收

2026-09-11。本次按收敛后的演示范围实施：保留预设案例，动态获取知乎材料，真实生成对谈，本机保存。没有新增账号系统、云端数据库或多人功能。

**演示入口**

打开 <http://127.0.0.1:8081/#/world/snail>。原 8081 预览服务已重新启动以加载更新后的后端。开发代码位于 `web/`，`releases/` 中的历史交付快照未改动。

1. 点击“案例与来源 / 获取新观点”。“获取更多知乎观点”优先读取 24 小时内缓存；“重新请求知乎”主动发起上游请求，同题请求间隔至少 60 秒。没有缓存时首次获取会调用上游。
2. 关闭面板，原有观点与新增观点同时保留。点击新增球阅读摘要和来源，再选择两颗球对谈。
3. 对谈方式默认“实时对谈 · 优先知乎直答”。点击下一位发言才调用模型。可加入新的主持人条件；新条件会中止等待旧回应并进入下一次请求。
4. 结束讨论，填写自己的理解并确认保存。记录留在本机，保留来源快照及真实发言的 provider、model、requestId、generatedAt。

离线演示仍可明确选择。实时请求失败、无凭证或额度受限时，只显示错误，不补入预设发言。自动模式优先使用已配置的知乎服务，未配置知乎时才使用已配置的兼容模型；不在知乎请求失败后自动切换服务。

**已实现**

| 范围 | 行为 |
| --- | --- |
| 问题取材 | 有固定问题 ID 的案例调用 question_answers，按服务返回的 NextOffset 翻页，每次最多两页；无固定 ID 的案例继续知乎搜索，每次最多两次 |
| 字段适配 | 分别处理 ContentToken/Summary 和 ContentID/ContentText；缺失作者时明确显示“作者信息未提供”，头像保持空白；一条有效摘要也可展示 |
| 案例保留 | 新材料按回答 ID 去重后追加，已有策划摘要、视角、ID 和规则继续保留，不被原始 API 文本覆盖 |
| 缓存与失败 | 显示缓存和重新获取的区别；空结果、异常分页、鉴权与配额失败保留旧内容；失败不写入新缓存 |
| 统一对谈入口 | 默认实时模式，包含碰撞入口；选择器和讨论中均可主动选择离线演示 |
| 临时条件 | 取消等待旧请求，过期结果不会插入当前对话；用户点击下一轮后带入最新条件和历史 |
| 本地记录 | 保存来源及每条真实发言的调用信息，仍使用原来的本机记录与导出流程 |
| 隐私配置 | 凭证只保存在仓库外的配置文件，权限 0600；仓库文本扫描未发现凭证值 |

主要改动位于 `web/zhihu_api.py`、`web/server.py`、`web/answers.js`、`web/app.js`、`web/relationship-ui.js`、`web/session.js` 和对应界面。

- 蜗牛案例真实调用 `question_answers`，一次请求取得 6 条有效摘要。回答 ID：451262338、483366139、450945882、451012053、451416885、1609186940。
- 其中 483366139 已属于预设案例，去重后新增 5 个观点；保留原有 4 个，画布共 9 个材料球，加上“我”为 10 个节点。
- 浏览器点击缓存按钮显示“已读取缓存，本次未请求知乎”；随后点击“重新请求知乎”显示“知乎已返回本题摘要”。重复来源没有制造重复球。
- 浏览器两轮真实直答均返回 HTTP 200，provider 为 zhihu，model 为 zhida-fast-1p5。
- 第一轮请求标识：`chatcmpl-d1fdcafc-f3e3-4a61-83b0-c8b8910d3d1f`。临时条件是“这笔钱不能购买交通工具”，回复讨论了交通方案受到的影响。
- 第二轮请求标识：`chatcmpl-c013f6a4-e3af-43f3-9f3c-05ba28ce62a1`。增加“只能依靠步行”后，请求包含两条主持人条件和前序对话，回复转向步行、每日随机位置及休息条件。
- 以上证明实际调用与上下文传递，不代表模型推断经过事实核实。原文、生成发言和用户确认的结论继续区分。
- 萝卜快跑通过搜索路径实际请求，但严格遵守 2024 年过滤条件后未取得有效新增摘要，应用返回 422 并保留预设案例。没有放宽历史条件或生成替代来源。

**测试与界面验收**

- JavaScript：29 项通过，包括追加去重、单条缓存结果、错误保留案例；同一工作区的既有交互测试也通过。
- Python：12 项通过，包括问题回答分页、空页游标、缓存隔离、坏分页保留旧数据、直答返回检查，以及真实模式失败不回退到兼容模型。
- 浏览器在真实两轮调用后注入了明确标注的 429 测试错误：错误正常展示，发言条数不增加，模式仍为实时。此项为故障模拟，不是上游实际限流。
- 浏览器用延迟测试回应验证主持人中途补充：旧回应被丢弃，下一轮按钮恢复可用。此项为竞态模拟，不消耗真实模型调用。
- 本机测试记录保存了 2 条带调用标识的真实发言；用同一隔离存储重新加载，记录和来源快照仍在。测试使用专用前缀，不覆盖用户原有历史。
- 手机尺寸 390×844：来源面板宽 352px，左右边界正常，无页面横向溢出。[画面](previews/live-api-mobile.png)
- 浏览器验收中没有未捕获 JavaScript 错误。

**使用边界**

接口只按演示所需显式触发，未批量预取所有案例。当前仍是本机预览，未发布公网。页面“整理”仍是原有的人工确认流程，没有宣称新增了 AI 自动总结或云端记忆。

凭证读取 `ZHIHU_ACCESS_SECRET`，或 `ZHIHU_SECRET_FILE` 指定文件；默认文件为 `/tmp/zhihu-probe/.secret`。临时目录可能被系统清理，重新配置时只需在安全配置位置更新凭证，不提交进仓库。

# 萝卜快跑案例与知乎 API 接入

核对日期：2026-09-11。在线官方文档优先于旧项目参考。**真实 API 调用尚待 Access Secret；当前页面为明确标注的案例演练。**

## 已核实的官方接口

| 能力 | 官方文档 | 适用范围 |
|---|---|---|
| 知乎搜索 | https://developer.zhihu.com/docs?key=zhihu_search | GET `/api/v1/content/zhihu_search`；`Query`、`Count` 最大10；新增 `SortBy` 可按 `EditTime` 区间筛选。返回作者、头像、ContentText 摘要、原链接及溯源参数。`HasMore` 固定 false，不做分页猜测。 |
| 问题回答 | https://developer.zhihu.com/docs?key=question_answers | GET `/api/v1/content/question_answers`；QuestionUrl、Offset、Limit。Summary 为摘要/截取，不是全文；当前文档未承诺作者头像。按 Paging.NextOffset 翻页，不按过滤后的数量推算。此次不调用。 |
| 知乎直答 | https://developer.zhihu.com/docs?key=zhida | POST `/v1/chat/completions`。只发送 model/messages/stream；上下文模型为 zhida-fast-1p5、zhida-thinking-1p5，具体受租户权限约束。 |

统一鉴权为 `Authorization: Bearer <Access Secret>` 和秒级 `X-Request-Timestamp`。OAuth app_key 与 Access Secret 不同。没有找到用于任意第三方答主全文的通用授权接口；“我的创作全文”不等于所有人的回答全文。

CLI 状态为未安装。本次是开发集成，依据在线 HTTP 文档编写服务端适配器，没有安装 CLI、生成用户凭证或请求个人账号数据。

## 案例

题目：无人驾驶越来越近，我们该以什么速度迎接它？

历史范围：2024 年（北京时间）。六个演练视角：技术发展、就业过渡、长期成本、安全证据、推广节奏、参与协商。它们是案例策划，不是虚构答主、不是群体民意分布；原兰大材料归档在 `web/cases/lanzhou-archive.js`。

背景阅读：
- https://36kr.com/p/2858899034806663
- https://www.thepaper.cn/newsDetail_forward_28111057
- https://www.thepaper.cn/newsDetail_forward_28111050

对谈条件：提供转岗支持、优惠结束、限定区域和时段。所有条件明确是假设，点击条件只填入输入框，点击“加入讨论”才生效。

演示路径：进入案例 → 悬浮阅读 → Agent × Agent → 技术发展与就业过渡 → 两次发言 → 加入转岗支持假设 → 两次发言 → 整理并保留记录。

## 实现

- `web/zhihu_api.py`：固定官方域名、固定案例查询，凭证只在服务端读取。禁止带凭证重定向，不把上游原始错误或密钥送入浏览器。
- GET `/api/case`：只读本地缓存，页面打开不消耗知乎额度。
- GET `/api/zhihu/status`：仅配置布尔值、缓存条数和同步时间，不声称配置就代表接口可用。
- POST `/api/zhihu/sync`：用户显式点击；最多两个搜索请求，Count=10。按 2024 时间范围与“萝卜快跑”相关性过滤，只收回答，按 ContentID 去重，最多展示8条。保留 UTM 链接。缓存24小时，锁保护并发，失败间隔60秒。
- 两次查询全部成功且至少两条有效回答后原子写入 `web/.data/robotaxi.json`（gitignore）；中途失败、空结果保留旧材料。
- 成功同步后页面重载，案例策划星球替换为真实摘要星球。头像没有时显示文字头像；不补造头像、昵称或原文。真实摘要默认关系待确认，不按热度、距离自动认定赞反。
- POST `/api/agent/turn`：provider=zhihu 走直答；原 OpenAI-compatible 适配保留。发言明确为 Agent 生成，引用材料不是指令，主持人的条件随上下文传递。无自动重试；最多6次发言。

## 本机配置

预览：`npm --prefix web run dev`，http://127.0.0.1:8081 。

优先读取环境变量 `ZHIHU_ACCESS_SECRET`；也可在 `/tmp/zhihu-probe/.secret` 保存凭证（已创建空文件，权限600）。使用其他路径时设置 `ZHIHU_SECRET_FILE`。文件内容每次请求读取，保存后不必重启。不要把凭证填进前端或仓库。

模型默认 `zhida-fast-1p5`，可通过 `ZHIHU_MODEL` 选择支持上下文的另一档。使用前仍需验证租户授权和实际返回。

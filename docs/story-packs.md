# 《未寄出的答案》故事包路线

## 统一后端，分阶段前端制作

四个故事包已进入同一份 `StoryPack` 目录、使用同一组试玩局与服务端结算接口。前端首个深度体验仍从《蓝血》开始，但其余三个不是文档占位，而是可以通过同一 API 创建并结算的故事包。

## 前端首发：《蓝血》

- 原作：知乎故事《蓝血》
- 作者：桃花先生
- 黑客松故事 `work_id`：`2025684191967294692`
- 首章：**急救培训之后**
- 游戏核心：玩家只改变信息被如何理解、先被谁看见；不改写原作角色命运或终局。

首章围绕“自我确认／公开伪装／他人注视”三条阅读线展开。玩家将四张**游戏解读卡**投递三张、压下一张，固定结算为“照见／错读／刺痛”。解读卡不是知乎回答，也不是原作续写；其作用是让玩家检查一条理解方式是否接上当下所缺的条件。

## 内容与署名规则

1. 每一个原作短引文必须能在本地同步的官方正文快照中逐字找到，并展示原作与作者署名。
2. 游戏解释、规则和复盘与原作文本分层标记；不得写成原作角色的新台词或作者续写。
3. 黑客松故事接口为本次活动专用能力。运行时读取审核后的故事包，接口同步失败必须如实提示，不能编造正文。
